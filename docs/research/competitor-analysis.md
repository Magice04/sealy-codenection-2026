# SEAL — Competitor / Alternative Analysis

This is a category-level comparison used for ideation. It is **not** an exhaustive market study and should not be phrased as “no product in the world does this”.

## What students can already use

| Category | Typical strength | Gap SEAL is targeting |
|---|---|---|
| Calendar tools | show fixed events and free/busy time | do not automatically explain how much unfinished effort fits before deadlines |
| Task managers | capture/organize tasks | can become long lists without a transparent time-capacity decision |
| Notes/workspaces | flexible organisation | require deliberate maintenance; structure is user-created |
| Pomodoro/focus apps | help start/continue work | focus cannot fix a plan missing 55 minutes |
| App blockers | reduce selected distractions | do not decide whether the schedule itself is feasible |
| Wellness/breathing apps | support relaxation | usually separate recovery from the actual task/deadline plan |
| OCR / scan-to-task features | reduce input friction | extraction alone does not tell the student what action to take |

## SEAL's intended position

SEAL combines several ordinary capabilities into a specific decision loop:

```text
IMPORT EXISTING INFORMATION
          ↓
STRUCTURE TASKS / EVENTS
          ↓
WORK TO FINISH vs TIME LEFT
          ↓
FOCUS / ADJUST / TAKE A BREAK
```

The differentiator is therefore **not** “we have OCR”, “we have a timer”, or “we have an island”.

It is the decision layer connecting:

- low-friction intake;
- effort estimates;
- calendar capacity;
- explicit shortfall;
- user-approved intervention.

## Example

A task manager may show:

- ISP640 Project Plan
- ICT652 presentation preparation
- ASC486 Group Project

SEAL's additional question is:

> **Do these actually fit before the deadlines?**

If they need 3h35 and only 2h40 remains, the answer is “no” and the product changes mode from productivity assistance to plan adjustment.

## Why Mentor #2 strengthened the positioning

The original five-load language risked making SEAL look like a generic “wellness score” dashboard.

The revised framing is more defensible:

> **SEAL is a workload-understanding and intervention system.**

Other life signals still matter, but the concrete core is visible and auditable.

## Claims we avoid

- “No competitor does anything similar.”
- “SEAL predicts burnout.”
- “Our load score is scientifically validated.”
- “AI knows when a student is exhausted.”
- “OCR automatically understands everything correctly.”
